# Kent Cars — технічне завдання

Дата: 15.10.2026. Основа: Discovery Interview із замовником.
Статус: погоджений напрям для локального демонстраційного сайту. Рекомендації нижче є рішеннями для реалізації, а не результатами дослідження клієнтів.

## 1. Контекст і ціль

Kent Cars займається пригоном авто зі США під ключ, підбором автомобілів в Україні та одноразовими оглядами. Основний продукт сайту — пригін зі США до передачі готового автомобіля клієнту.

Мета: емоційно представити компанію, пояснити процес і витрати, зняти побоювання щодо стану авто, передоплати й строків та привести відвідувача до заявки на консультацію й підбір під бюджет.

Перша версія — локальна демонстрація українською мовою. Це завдання на сайт; публікація та створення Telegram-бота не входять у поточний обсяг.

## 2. Метрики успіху

Для локального демо: працюють навігація, заповнення форми, валідація, деморозрахунок, відео та анімація маршруту на комп’ютері й телефоні. Немає помилок JavaScript і відсутніх ресурсів.

Після підключення приймання заявок: вимірювати початок і успішне надсилання заявки, конверсію відвідування в заявку, кліки на телефон і месенджери, використання калькулятора та частку кваліфікованих звернень. Числові бізнес-цілі визначити після отримання базової статистики; вигадані показники не встановлювати як обіцянку.

## 3. Цільова аудиторія і джерела трафіку

Люди в Україні, які хочуть придбати автомобіль вигідніше, ніж готовий аналог на місцевому ринку, та потребують супроводу процесу. Досвід купівлі зі США може бути відсутній.

Джерела: Instagram, TikTok, Google, Google Maps, рекомендації знайомих. Особлива увага мобільному перегляду.

Бюджети різні. Початкове формулювання $6–50 тис. не використовувати як перевірений діапазон повної вартості. Попередньо уточнено приклад: ставка $5–6 тис., повна вартість від $8–10 тис. Ці числа потребують перевірки на реальних кейсах перед публікацією.

## 4. Позиціювання і цінність

Простий, дружній супровід: пояснюємо зрозуміло, погоджуємо витрати, показуємо стан авто та допомагаємо пройти всі етапи. Конкурентне дослідження наведено в research.md: це добірка референсів і гіпотез без підтвердженої статистики конверсії. Названий конкурент — The Intertrade; його домен ще не уточнений, тому конкретні рішення йому не приписуємо.

Докази довіри: аналіз фото й опису лота, перевірка історії за VIN і Carfax, звіт про виявлені проблеми до купівлі, договір, погоджений розрахунок, реальні відгуки й видані автомобілі.

Не обіцяти абсолютну відсутність ризиків або гарантовано безпроблемне авто. Описувати конкретні перевірки та відомі обмеження. Не вигадувати стаж, кількість клієнтів, рейтинги чи відсоток економії.

## 5. Послуги та процес роботи

- Пригін автомобілів зі США під ключ — основна послуга.
- Підбір авто в Україні.
- Одноразовий огляд автомобіля.
- Доставка під дім по Україні; конкретну доступність адрес підтверджує менеджер.

За словами замовника, під ключ входять доставка, розмитнення, ремонт, сертифікація, постановка на облік і доставка клієнту.

Послідовність: звернення → уточнення бюджету й побажань → підбір і перевірка → звіт та погодження авто й витрат → оформлення домовленостей договором → передоплата перед торгами → торги та купівля → транспортування → розмитнення → ремонт і оформлення → передача клієнту.

Орієнтир від купівлі на аукціоні до передачі: 60–90 днів, без гарантії конкретної дати. Розрахунок включає всі очікувані витрати й погоджується до купівлі; фінальна сума може трохи змінюватися. Розмір передоплати та правила зміни кошторису ще не надані.

## 6. Обсяг першої версії та user journey

Рекомендований формат: одна довга сторінка з якірною навігацією. Окремий каталог, сторінки автомобілів, кабінет, CRM, оплати та адмінпанель не потрібні.

Happy path: відвідувач із соцмереж або пошуку бачить пропозицію → знайомиться з Олегом і компанією → переглядає кейси та перевірки → розуміє маршрут і строки → оцінює бюджет у демокалькуляторі → заповнює форму або телефонує.

Додаткові сценарії: людина не знає модель; хоче лише огляд; переходить одразу в контакти; віддає перевагу телефону; використовує клавіатуру або зменшення руху.

## 7. Дизайн-система і референси

Напрям: технологічний, емоційний, виразний. Чорний фон, кислотно-зелений бренд, білий текст, графітові поверхні, локальне зелене світіння.

Попередні токени: background #090B09, surface #181C18, accent #C4F000, text #F5F5F0, muted #B3B8AE. Остаточний зелений звірити з логотипом. На яскравих кнопках — темний текст; контраст перевірити.

Референс 1 NEXUS: великий жирний вузький шрифт, масштабна композиція, контраст чорного й лайма. Референс 2 Creatix: модульні блоки, різні розміри карток, заокруглення. Референс 3: зелене світіння, об’єм і м’які відблиски. Адаптувати принципи під автомобілі, не копіювати чужі тексти й брендинг.

Для заголовків підібрати виразний condensed-шрифт із повною українською кирилицею, наприклад Oswald; для основного тексту — Manrope. Використовувати локальні WOFF2 з відповідними ліцензіями. Перевірити І, Ї, Є, Ґ. Розміри — адаптивні через clamp(), базовий текст близько 16–18 px.

Сітка: до 12 колонок на широких екранах, одна або дві колонки на мобільних; послідовний крок відступів 8 px. Великі заголовки не повинні обрізатися. Світіння не знижує читабельність.

## 8. Бренд, власник і перший екран

Назва в текстах: Kent Cars. Власник: Олег Бордзань.

Логотип компонувати як на вивісці: знак ліворуч, вертикальний роздільник, праворуч KENT над CARS. Знак відтворювати за наданим зображенням; у розмові звучало KS, на графічному логотипі читається KC. Не перемальовувати його за текстовим припущенням.

Перший екран: Олег біля автомобіля на фоні офісу з вивіскою Kent Cars, великий заголовок, коротка ціннісна пропозиція, кнопка «Підібрати авто» та доступний телефон. Замовник дозволив створення такого зображення за референсами. Зберегти впізнаваність власника; напис на вивісці краще компонувати окремим точним графічним елементом.

Варіант слогана для демо: «Твоє авто зі США. Зрозуміло на кожному кроці». Альтернативи: «Від аукціону — до твого дому»; «Авто зі США. По-людськи, під ключ». Остаточний текст обрати під композицію.

## 10. Анімації та карта маршруту

Ключова сцена: стилізована карта світу, по якій у міру прокручування прокладається кислотно-зелена стрічка маршруту. Поступово змінюються точки, транспорт, зображення, підписи й орієнтовний час.

Етапи: аукціон у США → перевезення до порту → морська доставка → прибуття та доставка в Україну → підготовка й оформлення → передача під домом. Конкретні порти й транзитні країни не підтверджені: маршрут схематичний, не живий трекінг. Не вигадувати строки окремих етапів; до підтвердження показувати загальний орієнтир 60–90 днів.

Рекомендована реалізація: SVG-карта та path із прогресом промальовування, sticky-сцена й синхронізація зі звичайним scroll. На телефоні прокручування пальцем керує тим самим прогресом. Рух у зворотному напрямку коректно повертає попередній стан. Не перехоплювати коліщатко або touch і не блокувати вихід із секції.

Додаткова анімація: поява контенту, м’які переходи карток, реакції кнопок, локальне світіння. Не запускати всі ефекти одночасно. Анімувати переважно transform і opacity; уникати важкого blur на великих рухомих площинах.

При prefers-reduced-motion маршрут і етапи доступні статично, без довгої закріпленої сцени. Зміст зрозумілий без анімації й доступний у DOM.

## 11. Кейси, відгуки і команда

Кейс: модель, рік, фото, ставка окремо від повної вартості, склад витрат, строки, результат. Порівняння з українським ринком — лише для зіставних авто, із датою та джерелом орієнтира. Економія = порівняльна ринкова ціна мінус повна вартість під ключ. Немає даних — немає числової обіцянки.

Для кейсу передбачити фото до/після, дату, стан автомобіля, погоджений і фактичний кошториси та причини відхилень. Посилання на лот або допустимі дані VIN публікувати лише за наявності права на це. Невідомі дані не вигадувати. Кнопка «Хочу схоже» передає ідентифікатор кейсу й наявний бюджет у форму; введені користувачем значення не перезаписувати без його дії.

У замовника є реальні фото, відео, відгуки й історії; самі матеріали кейсів ще потрібно передати. Для демо допустимі явно позначені приклади. Не подавати вигадані цитати, ціни та результати як справжній досвід клієнтів.

Відео: постер, запуск натисканням, керування відтворенням, без автоматичного звуку. Передбачити текстовий виклад відгуку.

Для команди дозволені вигадані імена, ролі й згенеровані тимчасові портрети; позначка «Демонстраційна команда» обов’язкова до заміни. Олег — реальна особа, його дані не вигадувати. Постановочні AI-зображення не використовувати як докази виконаних замовлень.

## 12. Форма заявки

Одна компактна форма без окремого довгого квізу. Спочатку обов’язковий вибір «Пригін зі США / Автопідбір в Україні / Разовий огляд». Далі лише відповідні поля: для США — повний бюджет у доларах США, модель/кузов або «ще не знаю», бажаний строк, посилання на лот/VIN за наявності; для автопідбору в Україні — бюджет, модель/кузов або «ще не знаю», місто; для огляду — посилання на оголошення й місто. Ці уточнення та побажання необов’язкові, щоб залишити можливість консультації без визначеного авто. Ім’я й телефон обов’язкові та розташовані наприкінці. Приховані поля іншої послуги не впливають на валідацію поточної.

Показувати контекст обраного кейсу або розрахунку; бюджет залишається редагованим. Повторний перехід між блоками не стирає введення. Добірку й точний кошторис готує менеджер; автоматично знайдених авто не обіцяти.

Це справжні редаговані поля з підписами, зручною мобільною клавіатурою та зрозумілими помилками. Український телефон нормалізувати до +380; дозволити введення пробілів, дужок і дефісів. Не змушувати обирати модель, якщо людина ще не визначилась.

У локальному демо: дані нікуди не надсилаються, не зберігаються в аналітиці чи localStorage. Після валідного заповнення показати «Форму заповнено. Це тестова версія: заявку ще не надіслано. Зателефонуйте нам для звернення». Не показувати хибне «Заявку отримано» і не очищати поля як після успішного надсилання.

Пізніше підключити Telegram через окремий серверний endpoint. Підтверджувати успішне надсилання лише після відповіді сервера; передбачити помилку, повтор і захист від дублювання. Сам бот додається на фінальному етапі окремо.

## 13. Демонстраційний калькулятор

Мета — показати взаємодію й структуру орієнтовного бюджету. Це не точний митний або комерційний розрахунок.

Два способи введення: «Маю посилання на лот / VIN» та «Хочу оцінити авто за параметрами». В обох режимах користувач вручну вказує ціну лота й обирає умовний сценарій; у першому також додає посилання або VIN. VIN не запускає автоматичний пошук і не визначає ціну, логістику або стан. Відсутні параметри запитувати вручну або залишати для уточнення менеджером. Реальні інтеграції й актуальні комерційні тарифи не входять у локальне демо.

Результат — демонстраційний діапазон повної вартості в доларах США. Окремі складові: ціна купівлі, аукціонні збори, доставка територією США, морська логістика й порт, доставка до України/Луцька, митні платежі, брокер, ремонт і запчастини, сертифікація та реєстрація, послуга компанії, резерв. Не враховувати одну витрату двічі. Показувати дату конфігурації, припущення, включені й невключені витрати; ремонт до діагностики має невизначеність. Усі демонстраційні допущення та суми — в окремому конфігураційному файлі. Не видавати вигадані ставки за актуальні тарифи чи законодавчу формулу.

Постійна видима позначка «Демонстраційний розрахунок. Точний бюджет погоджує менеджер». Обробляти порожнє, від’ємне й нечислове введення; показувати валюту й підсумок. Кнопка «Обговорити цей бюджет» переносить діапазон, складові, режим, посилання/VIN за наявності й параметри у форму. Якщо бюджет ще не введений, заповнити його верхньою межею діапазону з явним поясненням; наявний бюджет не перезаписувати без дії користувача. Усі значення залишаються редагованими.

Перед публічним використанням потрібні перевірені тарифи, формули, дата актуальності та перелік того, що враховано.

## 14. Текстовий стиль

Лише українська. Простий, дружній, конкретний тон без складного жаргону й тиску. Термін аукціону або доставки пояснювати людською мовою. Звертання на «ти» — попередня редакційна рекомендація для демо.

Основні повідомлення: погоджуємо бюджет до купівлі; показуємо історію й відомі проблеми; працюємо за договором; супроводжуємо до передачі. Не писати «без ризиків», «найдешевше», «100% економія» або непідтверджене «завжди безпроблемні авто».

## 15. Технічний стек

Рекомендовано для реалізації: React + TypeScript + Vite, звичайний CSS із токенами, GSAP + ScrollTrigger для маршруту. SVG замість важкої 3D-сцени для карти. Версії залежностей і ліцензії перевірити при встановленні, зафіксувати lockfile.

Сайт запускається локально командами npm install та npm run dev; npm run build створює production-збірку, npm run preview дозволяє її перевірити. Остаточні команди описати в README відповідно до реалізації.

Контент і компоненти розділені. Мінімум залежностей. Поточній версії не потрібні база даних, сервер заявок чи зовнішні ключі.

## 20. Безпека та приватність

У демо особисті дані залишаються лише в стані форми поточного сеансу. Не логувати телефон чи текст заявки в консоль, зовнішню аналітику або URL.

Майбутній Telegram bot token зберігати тільки на сервері, не у VITE_* і не у клієнтському bundle. Для endpoint передбачити серверну валідацію, обмеження частоти, обмеження довжини полів, захист від спаму та екранування тексту для Telegram.

Перед реальним збиранням заявок додати погоджену інформацію про обробку персональних даних, одержувача й строк зберігання. Не вигадувати юридичні реквізити. Секрети не комітити. Для публічної версії — HTTPS.
